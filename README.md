# dsh-side-ask

在 DeepSeek Harness 的原生右侧栏里做「侧边提问」：从当前会话**分支**出一个临时会话，
带着当前会话已完成的上下文继续问，问完关闭标签就归档，不污染主会话。

- **右侧栏入口**：在右侧栏「新建标签页」的引导页（guide）里有一张「侧边提问」卡片，点它
  就在右侧栏打开本插件的**页面型标签**（`sidebar://sideask`）；会话标题栏也有一个
  「侧边提问」按钮（标签已存在时直接聚焦，不重复开）。
- **原生右侧栏 + 原生会话**：标签内容渲染的是**原生会话**（原生输入框、模型/权限、流式
  回复、停止按钮全部复用，经 `conversation.content` 工厂）。
- **继承当前会话记录**：标签页里的会话不是新会话，而是 `ctx.sessions.fork` 出来的分支
  （默认截在最近一个**已完成回合**），因此它带着主会话已完成的上下文继续问；主会话
  继续跑自己的任务，两边互不影响。
- **合并的选中弹层**：在会话里选中文字后，弹出的操作条里**并排两个按钮**——
  「引用文本」（等同官方引用，插入主会话输入框）与「侧边提问」（把选中文字组成
  Markdown 引用块，**预填**进侧边会话输入框，不自动发送）。右键手势也弹出同样的两项。
- **默认只读**：侧边会话创建时即切到宿主内置的 `read-only` 权限预设（sandbox 只读 +
  审批询问）——写文件、跑改文件的命令会被沙箱拒绝，读文件与网页检索仍可用。只有你在
  审批提示里主动允许提权时，单次操作才可能写成功；默认拒绝。
- **保留 = 持久会话**：标签页顶部「保留」把会话变成普通持久会话，并恢复父会话的权限
  （可写文件）；「改回临时」再切回只读。
- **默认归档，用户可保留**：侧边会话关闭标签后默认归档（不出现在会话列表）；标签页
  顶部有「保留」开关，打开后关闭标签也不再归档，它就是一个普通会话。

## 加载方式

加载方式：常驻（理由：UI 类——零工具、零提示词、零 skill，只注册右侧栏标签与选区入口，无每请求模型成本）。

> 加载方式是插件开发的必答项：按需的必须有 skill 入口与 `onDemand: false` 退路，
> 常驻的必须写理由。

## 安装

```powershell
# 从 GitHub 安装（公开仓库）
dsh plugin --profile desktop add github:lldwb/dsh-side-ask
# 或从本地目录安装
dsh plugin --profile desktop add <本地插件目录>
```

装完重启 DSH（Host 行与浏览器半一起重新加载），然后刷新页面。

要求 DSH **0.2.2-rc.5**（依赖该版本提供的右侧栏标签扩展点与 `sidebar.chat.conversation`
席位；更早的版本没有这些公开扩展点）。

## 使用

1. **右侧栏入口**：展开右侧栏 → 在标签条上点「+」打开引导页 → 点「侧边提问」卡片，
   右侧栏打开「侧边提问」标签。也可以点会话标题栏右侧的「侧边提问」按钮（同一个标签）。
2. 标签页里是一个从当前会话分支出来的临时会话：直接输入问题即可，回复是原生的流式输出。
3. **选中文字**：在会话里选中一段文字 → 弹出的操作条里并排两项：
   - 「引用文本」：把选中文字作为引用插入**主会话**输入框（官方 `message-quotes` 行为）；
   - 「侧边提问」：把选中文字作为引用**预填**进侧边会话输入框（不自动发送）。
4. 标签页顶部显示「临时会话 · 关闭标签后归档」。点「保留」后，关闭标签也不再归档。

## 行为细节

### 分支，而不是复制

侧边会话由 `ctx.sessions.fork({ sessionId })` 创建：截断点在**最近一个已完成回合**，
子会话继承主会话的历史（与 `dsh` 自带的「分支会话」是同一个引擎）、沿用主会话的
工作区与 Agent 预设。主会话后续的新消息不会同步进侧边会话，这是分支语义，不是缺陷。

如果主会话还没有任何已完成回合（全新空会话），fork 会失败；插件退化为在同工作区
新建一个空会话。

### 关闭即归档（默认）

宿主的 `ArchivedSessionGate` 会拒绝给已归档会话跑模型步，所以「默认归档」不能是
「创建即归档」。实际语义：

| 时机 | 侧边会话状态 |
|---|---|
| 标签页打开期间 | 未归档（能对话），会出现在会话列表里 |
| 关闭标签页（默认） | 归档（从会话列表消失），运行中的回合会被停止 |
| 关闭标签页（已点「保留」） | 保持未归档，就是普通会话 |
| 浏览器/宿主重启 | 标签页恢复时自动取消归档；没有标签页的遗留临时会话在启动 5 秒后归档 |

每个侧边会话的「保留 / 已归档」状态，以及「宿主会话 → 子会话」的绑定，都存在浏览器
`localStorage`（`dsh.side-ask.v2`，按会话 id 记录）；不写任何 Host 侧配置。

### 只读（临时会话的默认权限）

侧边会话不是普通会话，它只是「临时回答问题」：创建时插件就把它切到宿主内置的
`read-only` 权限预设（sandbox `read-only` + approval `ask`），发生在用户输入第一条消息
之前。效果：

- 写文件、跑会改文件的命令：被宿主沙箱拒绝（`file access denied under read-only mode`）；
- 读文件、glob/grep、网页检索：照常可用（回答问题的依据）；
- 模型请求提权（如 `workspace-write`）时，会走审批：**默认拒绝**；只有你在提示里明确
  允许「一次」才可能写成功。这是 DSH 只读预设的标准语义。
- 点「保留」后会话转为持久会话，插件把它切回父会话当时的权限预设（通常是
  `workspace-write`）；点「改回临时」再切回 `read-only`。

切换走的是官方同一条通道：浏览器半执行 `/permission <preset>` 斜杠命令
（`binding.session.command(...)`）——`permissionPresets.set` 这个 Host Remote 没有暴露
给浏览器端的生成命名空间，直接调用会得到 `...set is not a function`。

### 合并选中弹层：为什么接管官方 `quote` 表面

官方 `ctx.uiConversation.interactions` 是**独占式**的：`dispatch` 按注册顺序询问，第一个
调用 `open()` 的插件独占该手势的渲染表面。随附的 `message-quotes` 已经在 `selection`
手势上注册且永远 `open()`——再注册一个动作要么顶掉官方「引用」，要么永远轮不到。

要让「引用文本」和「侧边提问」**并排出现在同一个弹层**里，只能接管它渲染的表面：
`conversation.chat.text-interaction` 是 keyed 槽，按交互 id（`quote`）分发，
**同一个 key 用更低的 `priority` 注册即可 shadow 官方实现**（槽位规则：最低 priority 渲染）。
本插件因此：

- 在 `quote` key（`priority: -1`）注册自己的双按钮组件——「引用文本」完整复刻官方行为
  （`inputActions.insertQuote(text)` + 清选区 + 关弹层），旁边并排「侧边提问」；
- 用本插件自己的 key 注册同一组件兜底：官方 `message-quotes` 缺席、或右键手势（官方只处理
  selection）时同样弹出这两项；
- 插件卸载后官方表面自动恢复。

### 页面型标签与子会话绑定

标签是页面型（`sidebar://sideask`），不注册资源协议：子会话 id 由本插件按「宿主会话」
记录在 `localStorage` 里，标签打开时取出渲染；重载后标签与绑定都还在。从引导页打开时
标签里还没有子会话，标签正文会在挂载时为本会话创建一个（已有绑定则复用，不重复 fork）。

### 不递归嵌套

侧边会话自己的标题栏不会再出现「侧边提问」入口（`store.isChild` 判断）；侧边会话里选中
文字时，合并弹层只显示「引用文本」一项。侧边会话再分支没有语义，只会堆会话。

### 为什么声明了一个「私有的 session 子槽」

右侧栏标签内容要渲染**子会话**的原生会话，需要框架注入的 `SessionProvider`；而
`SessionProvider` 只在「本注册声明了非 root 作用域的子槽」时才提供（`ui-renderer` 的
`standardProps` 分支）。随附 `ui-subagent` 已经全局声明了 `sidebar.chat.conversation`，
第三方再声明同一个 key 会抛 `slot "sidebar.chat.conversation" is already declared`。
因此本插件声明了一个自己命名的、**只声明不渲染**的 session 子槽
（`dsh-side-ask.side-session`）来触发 `SessionProvider` 注入，再用它包住
`renderFactorySlot('conversation.content', { variant: 'embedded', … })` 渲染原生会话。
如果将来 DSH 改变这条注入规则，标签内容会显示「当前部署没有可用的侧栏会话组件」而不是崩溃。

1.0.4（临时会话只读 + 保留恢复权限）：
